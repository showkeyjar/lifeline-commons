# 架构（轻量版）

```
┌─────────────────────────────────────────────┐
│ 治理 / 公地层                                   │
│ 规则 · 社区决策 · 反圈地 · 资金托管              │
├─────────────────────────────────────────────┤
│ 编排层 · Lifeline OS                           │
│ 需求感知 → 资源调度 → 供给交付（闭环）          │
├─────────────────────────────────────────────┤
│ 供给模块层（可插拔 · 各自独立开源）               │
│ 食物 │ 能源 │ 住所 │ 健康 │ 照护 │ 教育          │
└─────────────────────────────────────────────┘
```

## 为什么这么分
- **会被推翻的**：供给模块的"具体实现"。今天用模拟/初级自动化，未来换成更强能力——没关系，设计成可插拔。
- **不会被推翻的**：治理规则、模块接口标准、规范性原则。这些能力无关，且未来智能越强越重要。

## 设计纪律
**让接口比实现活得更久。** 稳定接口 + 可换后端，今天写的不是会被推翻的机器，而是未来更强机器要插进去的插槽与规则。
