# 多语言指南 / Internationalization Guide

Lifeline Commons 的工具输出与文档支持多语言。当前支持：**中文 `zh`**、**English `en`**、**Español `es`**。
本文件说明如何新增语言、以及现有结构。

## 1. 工具输出的多语言（代码侧）

所有面向人的字符串集中在 `lifeline-os/i18n.py` 的 `CATALOG` 字典里，按语言键组织：

```python
CATALOG = {
    "zh": { "title.lifeline": "# 生存自由报告（Lifeline OS）", ... },
    "en": { "title.lifeline": "# Survival-Freedom Report (Lifeline OS)", ... },
    "es": { "title.lifeline": "# Informe de Libertad de Supervivencia (Lifeline OS)", ... },
}
```

代码里只写 `i18n.t("some.key", **kwargs)`，不直接写文案。例如：

```python
import i18n
i18n.set_language("en")
print(i18n.t("title.lifeline"))                 # Survival-Freedom Report (Lifeline OS)
print(i18n.t("ff.compose", pct=80, top=70, qual=60))
```

### 运行 / 切换语言

```bash
python lifeline-os/lifeline.py --lang en          # 英文生存自由报告
python lifeline-os/lifeline.py --lang es          # 西班牙文
python lifeline-os/strategy_analyzer.py --lang en # 英文策略报告
python lifeline-os/orchestrator.py --lang en      # 英文社区报告
```

### 缺失键行为

- 当前语言的键缺失 → **回退到中文**（源语言），不会让报告出现空白或崩溃。
- 中文源语言也缺失 → 返回**键本身**（便于发现漏翻）。

### 自检

```bash
python lifeline-os/i18n.py --check   # 检查 en/es 是否覆盖全部中文键
python lifeline-os/i18n.py --list    # 列出支持的语言
```

CI（`smoke.yml`）目前跑中文闭环；新增语言后建议也把该语言的冒烟纳入 CI。

## 2. 用户数据值的可选翻译

画像里由用户提供的**分类值**（如所在地 `乡村/郊区/城市/离网`、健康 `良好/受限`）在英文/西文报告中也会被翻译，
通过 `loc.*` 与 `health.*` 键实现；中文保持原值，未登记的值原样返回。
技能（`skills`）等自由文本目前不翻译——它们是用户自述的专有名词。

## 3. 如何新增一种语言

1. 在 `lifeline-os/i18n.py` 的 `CATALOG` 里加一个键，例如 `"fr": { ... }`。
2. **完整复制中文（`zh`）的全部键**并翻译（键名必须一致，否则 `--check` 会报缺失）。
3. 在 `SUPPORTED` 元组里加上新语言代码。
4. 跑 `python lifeline-os/i18n.py --check` 确认零缺失。
5. （可选）把 `docs/` 下的重要文档翻译成新语言，放到 `docs/<lang>/` 目录（参考 `docs/en/`）。
6. 在 `README.md` 的语言导航里补上新语言的链接。

## 4. 文档的多语言

- 项目门面：`README.md`（中文）/ `README.en.md`（English）。
- 接口规范：`docs/module-interface-v1.md`（中文）/ `docs/en/module-interface-v1.md`（English）。
- 其他文档（可行性、蓝图、社区手册等）目前仅中文；欢迎贡献翻译，按 `docs/<lang>/` 组织。

## Internationalization Guide (English)

The project's tool output and docs are multilingual. Supported: **中文 `zh`**, **English `en`**, **Español `es`**.

All human-facing strings live in `lifeline-os/i18n.py` as a `CATALOG` keyed by language. Code only calls `i18n.t("key", **kwargs)`.

- Missing key in the active language → **falls back to Chinese** (the source language); reports never go blank.
- Missing in Chinese too → returns **the key itself** (so you notice the gap).

Add a language: copy all `zh` keys into a new `CATALOG` entry, translate, add the code to `SUPPORTED`, then `python lifeline-os/i18n.py --check`.
