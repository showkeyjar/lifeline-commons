# 生存自由指数（Survival Freedom Index）

> 配套代码：`lifeline-os/lifeline.py`。本文解释它怎么算、为什么这么算、以及它**不**是什么。

## 它解决什么问题

项目核心诉求是：**机器人（这里是软件协调层）先分析主人/社区的最佳生存策略，目标是让主人实现"生存自由"——无需依赖市场工资或被巨头供给，也能被基本生存需求覆盖。**

但"策略推荐"（[`strategy_analyzer.py`](https://github.com/showkeyjar/lifeline-commons/blob/main/lifeline-os/strategy_analyzer.py)）和"供给模拟"（[`orchestrator.py`](https://github.com/showkeyjar/lifeline-commons/blob/main/lifeline-os/orchestrator.py) + `modules/*`）原本是**脱节的半截**。本文件描述的闭环把它们接起来：

```
画像 → 策略分析器推荐策略 → 把画像喂给供给层模拟 → 综合成"生存自由指数"
```

## 两个关键建模量

### 1. 人口（需求侧）
每个模块的 `assess_needs(context)` 已经按 `context["population"]` 缩放日均需求（电 kWh、餐、水 L）。人口越多，需求越大。

### 2. 资产规模系数 `asset_scale`（供给侧）
这是本次新增的、让模拟**真正吃进画像**的关键量。含义：

> 主人实际能建起的产能，相对"12 人基准社区"的比例。1.0 = 持有与基准社区匹配的产能。

由 `compute_asset_scale(profile, 推荐策略)` 推算：
- 启动资本越足 → 越能堆资产（资本 0/1/2/3 → 系数 0.4/0.7/1.0/1.3）
- 有地 → 额外 +0.3（可开荒/自建）
- 依赖收入/迁移/外部托底的策略不靠物理资产，系数上限压低（0.7 / 0.3）

系数透传到每个模块的 `schedule → provide → _simulate`，**产能（发电/产量/储水）与储能/库存容量同比缩放**。需求随人口缩放、产能随资产缩放，于是覆盖率会随画像真实变化：

- 小家庭持全套资产 → 过剩（覆盖率封顶 1.0，有余量）
- 大家庭吃 12 人资产 → 出现缺口（覆盖率 < 1.0）
- 资产系数减半 → 必然缺口

## 生存自由指数怎么算

```
freedom = w_s · 供给覆盖得分 + w_t · 策略匹配得分 + w_q · 定性韧性得分
```

- **供给覆盖得分** = `min(1.0, 各域平均覆盖率) × 100`。物理自给型策略最看重它。
- **策略匹配得分** = 策略分析器给首选策略的匹配分（0–100）。
- **定性韧性得分** = 健康良好 +25、家庭 ≤4 人 +15（≤8 人 +5）、有地或在郊区/乡村/离网 +10，基线 50，封顶 100。
- **权重 `w_s / w_t / w_q`** 随策略不同（三者和为 1）：

| 策略 | 供给 w_s | 策略 w_t | 韧性 w_q | 说明 |
|---|---|---|---|---|
| 分布式自给 | 0.60 | 0.25 | 0.15 | 物理自给，最看重产能 |
| 城市社区协作 | 0.50 | 0.30 | 0.20 | 协作+分工 |
| 半自给+缓冲 | 0.50 | 0.30 | 0.20 | 降开销为主 |
| 低成本迁移 | 0.25 | 0.45 | 0.30 | 靠低生活成本，不堆资产 |
| 技能变现 | 0.25 | 0.45 | 0.30 | 靠可携带收入 |
| 外部托底 | 0.15 | 0.50 | 0.35 | **封顶 30 分** |

分档：≥80 高 / 60–79 中高 / 40–59 中 / <40 低。

## 诚实边界（它不是什么）

1. **不是承诺，是一阶线性规划工具。** 产能/需求同比缩放只是第一近似；真实落地前必须用社区真实数据替换 `modules/*/data/`。
2. **纯外部托底路径被封顶 ≤30 分并明确标注"本项目帮不了"。** 无地、无资本、无可变现技能的人，只能靠政府现金底/基础服务——这部分超出项目范围。
3. **不替人决策、不交付机器人、不解决人生意义。** 指数只是帮主人/社区看清"我现在离生存自由多远、卡在哪"，决策权在执行者手里。
4. **供给模拟对极小家庭的覆盖率会显示 100%**（一个人需求极小，任何资产都显过剩）——这是模型的机械结果，不构成"已自给"。真正的结论是自由指数 + 诚实边界那一段，而非覆盖率表本身。

## 怎么扩展

- 想加新域（住所/健康）：在 `modules/` 下新增合规模块，`lifeline.py` 会自动发现并纳入覆盖率均值。
- 想改权重/打分：改 `lifeline.py` 顶部的 `STRATEGY_WEIGHTS` / `CAPITAL_FACTOR` / `_qual_score`。
- 想换更精细的产能模型：替换各模块 `data/` 下的样例数据或 `_simulate` 实现，接口不变。
