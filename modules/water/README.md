# 本地水模块（water）

数据驱动参考实现（阶段 1）。读取本地样例数据（雨水 + 井水产量预测 + 储水罐状态），
做 **30 天自给模拟**，输出**社区自给覆盖率**（供应 ÷ 需求）。

## 逻辑
`本地雨水/井水生产 → 储水罐补缺 → 仍不足如实记缺口`；**余量入库、不卖**。
自给优先顺序：`rain-harvest → well → community-tank`。

## 样例数据（modules/water/data/）
- `config.json`：12 人 / 每人 50 L·天（生存基线：饮用+炊事+基本卫生）
- `tank.json`：储水罐容量 1000 L、初始 300 L、最低储备 200 L
- `supply_forecast.csv`：30 天雨水 + 井水产量（井水按可持续出水量恒定，雨水随旱季走低）

## 跑出来的真实数字
```
需求: 600 L/天（12人）
平均自给率: 0.991
满供天数: 28 / 30
缺口天数: 2（第22、23天，旱季+储水罐触底，覆盖率 0.83 / 0.88）
最低储水: 200 L（触底保护）
```
最弱的那两天被如实标出来——调大储水罐或井水出水量即可消除。

## 范围声明
本模块只算**社区自身自给覆盖率**，不做余水出售、水权交易、虚拟水市场等任何交易逻辑。
与本项目「排除交易」的定位一致。

## 未来替换方向（实现可换，接口留住）
- 真实雨量计 / 水位计 / 水表数据接入，让 `assess_needs` 从估算变实测
- 开源雨水收集 + 井泵 + 过滤消毒方案（如基于 Arduino/ESP32 的水位与泵控）
- 灰水回收系统接入，降低净需求

## 接口（module-interface-v1）
实现 `name / provides / assess_needs / schedule / provide / status` 六方法，
契约由 `lifeline-os` 自动校验、由 CI 单元测试守护。
